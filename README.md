# KeyCount

安静待在菜单栏里的本机写作计数器。支持 macOS 13 及以上。

## 1.7.0 置顶悬浮窗

新增一个常驻桌面的半透明悬浮窗，始终浮在其他窗口（含全屏应用）之上，
实时显示当前主要指标的数字与速度。偏好设置 → 悬浮窗开启。

- **不抢焦点**：用不激活的面板（`.nonactivatingPanel` + `orderFrontRegardless`）。
  这是硬要求——一旦抢焦点就会改变前台应用，净字数引擎会误判。
- **始终置顶**：窗口层级 `.floating`，并加入 `canJoinAllSpaces` 与
  `fullScreenAuxiliary`，切到别的桌面或全屏也看得到。
- **半透明**：背景用 `.ultraThinMaterial`，整体不透明度 0.3–1.0 可调。
- **可拖动、记位置**：拖窗体任意处即可移动，位置记在 UserDefaults；
  下次仍落在可见屏幕内，否则回到右上角。
- **鼠标穿透（可选）**：开启后点击落到下方窗口，适合长时间挂着不挡操作；
  此时不可拖动，需关闭后再移动。

悬浮窗跟随主要指标切换，内容复用面板的快照逻辑，不读历史、不扫盘。

## 1.6.0 主指标可选

主指标从「净字数」改为可选三项，默认看**敲键字符**：

| 指标 | 含义 | 依赖权限 | 覆盖面 |
| --- | --- | --- | --- |
| 敲键字符（默认） | 敲出来的可打印字符数，拼音每个字母各算一次，只增不减 | 输入监控 | 所有应用 |
| 上屏字数 | 实际上屏的字数，只增不减；中文按字、英文按词 | 辅助功能 | 能暴露文本的应用 |
| 净字数 | 上屏 − 删减，可能为负 | 辅助功能 | 能暴露文本的应用 |

净字数回答的是「今天净留下多少」，适合写长稿反复删改时看；
敲键字符与上屏字数回答的是「今天打了多少」，不会因为删改而回落。

选择会同时作用于菜单栏数值、面板主数字、每日目标、速度卡和七天趋势图；
未选中的两项仍在面板里并排显示。权限提示也跟着主指标走：
选敲键字符时缺的是输入监控，选另两项时缺的是辅助功能。

同批补上：键盘侧也记录今日峰值速度与活跃分钟（此前只有文本侧有），
按日文件新增 `peak` 与 `minutes` 字段，历史汇总同时读取
`chars`（敲键字符）与 `added`（上屏字数）。

### 覆盖面实测

用 `diag.flag` 走应用自己的读取路径逐个测过：

- 完整可读：文本编辑、终端（整屏回滚缓冲）、Chrome 与 Safari 的
  `input` / `textarea` / contenteditable、Comate 的聊天输入框。
- 只读到一部分：Monaco（VSCode 内核）只暴露光标附近约 10 行，
  40 行文档读到 330 / 1319 字符。移动光标会整体改写这段内容，
  靠 1.5.0 的按键佐证排除，不再凭空增减。
- 读不到：Microsoft Word（焦点元素是 `AXSplitGroup`）、
  旧版 Electron（完全不暴露无障碍树）、焦点停在 `AXWebArea` 容器时。

敲键字符不依赖这条链路，上面读不到的应用也照常统计。

## 1.5.0 计数准确性

这一版的主题是「AXValue 变了，不等于人打了字」。此前只要焦点控件的文本变化
就按字数差计入，于是 AI 流式输出、终端回显、文档加载与云同步、自动格式化、
在同一个控件里切换文档，都会被当成写作：新增侧有 150 字上限兜底，
删除侧完全没有上限，切一次文件就可能凭空倒扣几千字。

现在每一次文本变化都要同时过两道判据：

- **佐证**：两秒内必须有会改动文本的按键（可打印字符、删除、回车、Tab），
  否则判为程序化改动，只推进基线、不计数。
- **预算**：计入的字数不能超过这段时间的按键所能产生的量
  （固定余量 + 每键 4 字 + 上一次轮询读到的选中长度）。
  选中一整段后一键删除照常扣减，没有选中时单键删不掉 120 字。

其余同批修订：

- 粘贴、剪切、撤销、重做按下后的 0.6 秒内不计入文本变化，也不会倒扣。
- 控件基线改用 `CFEqual` 判等（此前只比 `CFHash`，不同控件撞哈希会共用基线），
  并按「最久未见」淘汰，上限 32 个，长期运行不再无上限增长。
- 密码框（`AXSecureTextField`）不读不计。
- 「敲键字符」只计真正可打印的字符：方向键、F1–F12、Home/End、翻页、
  回车、Tab 不再混进去。
- 活跃分钟改为落盘明细，重启后继续按分钟去重累加（此前会卡在重启时的数值）。
- 按日文件名固定公历，不随地区日历变化，避免当天数据在历史图表里消失。
- 计数逻辑集中到 `CountingEngine.swift`，测试直接跑这份实现，
  不再维护一份会漂移的副本。

没有按键可佐证的输入方式（语音输入、手写板）不计入。
只授予辅助功能、未开输入监控时无法核对按键，退回纯体量约束，计数会偏松。

## 1.4.1 授权流程修订

- 未授权时不注册全局或本地键盘监听；辅助功能、输入监控均允许后才注册。
- 定时检查只读取授权状态，不请求权限；授权/撤销时只启动或停止一次。
- 授权按钮每次进程运行最多请求每项权限一次，后续点击只打开系统设置。
- 从只读卷（例如 DMG）运行时暂停监控、落盘及授权请求，提示先安装。
- 偏好设置可复制运行路径、签名和权限诊断信息，便于检查是否运行了旧副本。
- 临时签名包必须用 `--local` 明确打包；默认不再把它当作正式分发包。

这些改动消除代码侧的重复触发风险，不等于已验证每台机器的系统授权状态。
ad-hoc 签名的 designated requirement 包含构建内容的 cdhash，
不能作为跨构建稳定的发布者身份。GitHub Release 可以发布未公证的 ad-hoc 包，
首次安装需按下文手动允许，更新后可能需要重新授权。Developer ID 与公证是可选的
分发升级方案，也不替代用户对辅助功能、输入监控的授权。

- 专用单色菜单栏图标，随系统自动适配浅色、深色及选中状态。

## macOS 安装

从 GitHub Release 下载与你的 Mac 对应的 `.dmg`：Apple Silicon（M 系列芯片）
选择 `arm64-local.dmg`，Intel Mac 选择 `x86_64-local.dmg`。

1. 打开磁盘映像，把 `KeyCount.app` 拖到“应用程序”文件夹。
2. 推出 `.dmg`，再从“应用程序”文件夹启动 KeyCount。
3. 如果 macOS 提示无法验证开发者或应用未公证，打开“系统设置 → 隐私与安全性”，
   在安全性区域点击“仍要打开”，随后在弹窗中点击“打开”，按提示完成认证。

GitHub Release 提供 ad-hoc 签名、未公证的 DMG，无需关闭 Gatekeeper。
首次安装或更换构建后可能需要再次允许打开或重新授予权限。
辅助功能和输入监控权限仍需按应用内提示单独开启；不要从 DMG 内长期运行应用。

### 本机构建签名

签名身份按此优先级选择，脚本从不自动导入私钥：

1. 显式 `KEYCOUNT_SIGN_ID`（如 Developer ID）；
2. 否则用**固定自签名身份** `KeyCount Dev`（先准备本机私有的 `certs/` 文件并运行
   `./scripts/import_signing_cert.sh`）；
3. 都没有则回退 **ad-hoc**。

固定自签名把 designated requirement 绑定到证书
（`identifier "com.local.keycount" and certificate leaf = H"…"`）而非 cdhash，
因此每次重新构建身份不变，**macOS 的辅助功能/输入监控授权可跨版本保留**。
ad-hoc 则每次构建 cdhash 都变，更新后往往要重新授权。
重新构建时保留旧工作区应用于 `.build/local/previous.*`；
安装时也会先备份已有应用，不删除统计数据。

### 固定自签名（推荐，解决"更新后反复授权"）

```bash
./scripts/import_signing_cert.sh   # 一次性：把 certs/ 里的 KeyCount Dev 导入专用钥匙串
./build.sh                         # 之后自动用它签名
```

脚本创建专用钥匙串 `~/Library/Keychains/keycount-signing.keychain-db`，
用本地口令授权 `codesign` 无弹窗使用私钥。签名私钥和证书只应放在本机的
`certs/` 目录中；该目录已被 Git 忽略，**不会提交到仓库**。此身份仅供本机自用。
自签名**未公证**：首次被拦截时按上面的“仍要打开”流程操作。从 ad-hoc 切到自签名时，
系统会把它视为新身份，需**再授权一次**；此后更新不再丢授权。
建议同时在"系统设置 → 隐私与安全性"里删掉历史遗留的多个 KeyCount 条目。

项目仍采用 Swift 5 语言模式，无外部包依赖。脚本优先使用本机已安装、版本不高于
当前系统主版本的 SDK。可用 `KEYCOUNT_SDK=/完整/SDK/路径 ./build.sh` 覆盖。
如果 SwiftPM 在 `PackageDescription` manifest 阶段发生工具链不匹配，脚本会针对
本项目无依赖的结构改用 `swiftc` 直接构建。也可运行 `./build.sh --direct`。
真正的源码编译错误不会被此回退吞掉。原始日志保存在 `.build/local/swift-build.log`。

如需用自己的正式身份（Developer ID，可公证分发）：

```bash
KEYCOUNT_SIGN_ID="Developer ID Application: YOUR NAME (TEAMID)" ./build.sh
```

签名与公证是两件事；默认产物未公证，脚本生成本机架构的二进制，
Release 流水线分别构建两种架构。不要公开提交私钥或签名身份。
`./make_dmg.sh` 不带 `--local` 时仅接受 Developer ID 签名的应用。
文件名包含版本和架构（测试版额外含 `-local`），`dist/KeyCount.dmg` 同步指向本次内容。

## 权限与隐私

首次运行只显示引导，不主动发起系统授权请求。

- **辅助功能（必需）**：点击面板里的授权入口，在系统设置允许 KeyCount。
  用于读取当前文本控件的值，在内存中比较字数变化；授权后自动复查。
- **输入监控（可选）**：在偏好设置单独开启，用于按键计数与小时分布。
  全局键盘监听还需要辅助功能；如果 macOS 要求退出并重新打开，请按系统提示操作。
- **登录启动**：仅在已签名的 `.app` 中使用；如系统要求批准，界面显示操作提示。

原文只在进程内存中用于差值比较；落盘的是每日汇总，不上传。
数据仍保存在 `~/Library/Application Support/KeyCount/`，沿用原有 JSON 格式。
手动启用 `diag.flag` 时会额外记录应用名、控件类型和长度等诊断元数据，但不记录原文。

上屏字数与净字数是估算：中文按字（含部分全角标点）、英文/数字按词；
只有与按键对得上的文本变化才计入，粘贴与程序化写入略过，
清空可能被视为发送而不扣减；不暴露辅助功能文本的应用无法统计。
这不是文档总字数。敲键字符是另一套口径，直接数可打印按键，
因此拼音输入下它明显大于上屏字数。
面板底部与偏好设置里会显示本次运行跳过的非人工改动次数，可用来自查。

### 换机器或更新测试包后反复提示

1. 退出所有 KeyCount 副本，将应用放入 `/Applications/KeyCount.app`。
2. 推出 DMG，从“应用程序”打开，而不是继续运行下载目录或 DMG 内的副本。
3. 若系统已勾选但应用仍显示未授权：先退出 KeyCount，在对应权限页移除旧的
   KeyCount 条目，重新添加“应用程序”里的当前版本并开启，然后再启动。
4. 若仍异常：偏好设置 → **复制授权诊断信息**，附上弹窗截图与对方 macOS 版本。
   诊断中包含用户目录路径，分享前可隐去用户名；不含输入内容。

不自动运行 `tccutil`，不读写 TCC 数据库，不关闭 SIP/Gatekeeper，
不自动导入私钥，不通过宽松的代码签名要求规避系统授权。
包内也包含 `安装与授权说明.txt`。

## 发布

Release 流水线使用 ad-hoc 签名，不需要 Apple 开发者账号、Developer ID 证书或公证凭据。
推送与 `Resources/Info.plist` 中版本号一致的标签，例如：

```bash
git tag v1.7.0
git push origin v1.7.0
```

流水线会在 Apple Silicon 和 Intel runner 上分别运行测试、构建应用、生成未公证 DMG。
两种架构都成功后，自动发布 GitHub Release，附上两个 DMG、`SHA256SUMS` 和安装说明。
任一架构测试或构建失败，都不会执行发布。

也可在 Actions 的 Release 工作流中手动运行，填写已有标签（如 `v1.7.0`）；
构建内容始终取自该标签。已发布的版本不会自动覆盖，后续更新请提升版本号并创建新标签。
在本机打包可运行 `./build.sh` 后再运行 `./make_dmg.sh --local`。
